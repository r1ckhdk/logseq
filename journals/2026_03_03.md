- [[RNP - Administração de Sistemas Linux]]
	- **Módulo 8 - Boot & Shutdown e Kernel
		- Inicialização do sistema
			- Detecção e teste do hardware existente
			- Carregamento do software que gerencia a inicialização
			- Acesso ao dispositivo que será utilizado para iniciar o processo de boot
			- Carregamento do gerenciador de boot
			- Inicialização do kernel e initramfs
			- O kernel inicia o processo responsável por inicializar os demais serviços
			- **Basic Input/Output System (BIOS)**
				- Controla os primeiros passos do processo de boot
				- Fornece o I/O básico para os dispositivos de armazenamento
				- Testa o hardware do sistema
				- Realiza carga do programa presente no MBR
			- **Unified Extensible Firmware Interface (UEFI)**
				- Inicialização mais rápida
				- Interface gráfica elaborada com suporte ao uso do mouse
				- Proteção contra malwares e rootkits que atuam no pré-boot
				- Suporte para partições GPT e MBR
			- Carregadores de boot (bootloaders)
				- Permitem que o adm escolha qual sistema desja iniciar
				- Responsáveis por carregar o kernel do Linux na memória
				- Ex.: GRUB, Lilo, Chameleon, NTLR, BURG, rEFIt
			- Iniciando o kernel
				- As imagens do kernel ficam localizadas no diretório /boot
				- Normalmente possuem o nome vmlinuz + sufixo que indica a versão, por exemplo: `/boot/vmlinuz-4.10.0-40`
				- Monta a imagem initial do RAM disk (initrd)
				- Carrega todos os módulos necessários
				- Monta a partição raiz
			- Iniciando os demais serviços
				- Após o carregamento do kernel na memória é iniciado o processo responsável por carregar os demais processos do SO
					- systemd PID = 1
						- default.target
			- Mensagens de boot
				- **dmesg**
					- Mensagens armazenads no buffer do kernel
					- Permite filtrar as mensagens por facilidade (-p) e prioridade (-l)
					- Apenas as mensagens do último boot
				- **journalctl**
					- Pode armazenar as mensagens de boot de forma persistente
					- Com a opção -b exibe as mensagens de boot do sistema
						- -b 0 = boot atual
						- -b -1 = último boot antes do atual
			- **GRUB - Grand Unified Bootloader**
				- Gerenciados de boot padrão do Linux
				- Permite a passagem de parâmetros para o kernel
				- Suporte para BIOS e UEFI
				- Consegue ler diversos tipos de partições como: ext2, ext3, ext4, Reiserfs e NTFS
				- GRUB 2
					- /boot/grub2/grub.cfg
					- /etc/default/grub
					- /etc/grub.d/ > /etc/grub.d/40_custom
					- Após realizar as modificações desejadas atualize o GRUB
						- `# grub2-mkconfig -o /boot/grub2/grub.cfg`
			- **systemd**
				- Unit files
					- Diretórios
						- `/lib/systemd/system`
						- `/etc/systemd/system`
					- Arquivos unit
						- service: controlar daemons e processos
						- socket: gerenciam sockets IPC ou de rede
						- target: agrupar outras units
						- device: units que representam dispositivos para o systemd
						- mount: controlam mount points
						- automount: fornecem recursos para a montagem automática
						- path: units para gerenciamento de um caminho no sistema de arquivos
		- Arquitetura do kernel
			- Kernel monolítico
				- É composto por um grande e único bloco de código
				- Carrega estaticamente os drivers de dispositivo definidos
				- Ocuma mais espaço da memória uma vez que os drivers de todos os dispositivos configurados são carregados, independentemente de estarem instalados no sistema
				- Utilizado em sistemas operacionais como Linux, FreeBSD, versões antigas do Windows (95, 98, ME) etc.
			- Kernel modular/híbrido
				- Carrega dinamicamente os drivers de dispositivo detectados na inicialização do sistema
				- Os módulos são carregados sob demanda e podem ser removidos da memória após um intervalo de inatividade
				- Ocupa menos espaço em memória
			- Comandos para gerencias módulos
				- `kmod`: carrega em memória módulos automaticamente sob demanda
				- `modprobe`: carrega ou remove da memória manualmente um módulo e **suas dependências**
				- `insmod`: carrega em memórua um módulo, mas não carrega suas dependências
				- `lsmod`: lista os módulos carregados em memória
				- `modinfo`: exibe infos sobre o módulo
			- Configurando os componentes do kernel
				- Código fonte armazenado no diretório `/usr/src/linux`
					- Variáveis que representam os componentes do kernel
					- Pode ser alterado através de um editor de textos
					- Também pode ser alterado através do comando make
